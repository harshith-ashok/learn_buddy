# 0006: Deterministic text for recommendation justifications and remediation plans

## Problem

`recommend_next_topic` needs a "one-line justification" and
`trigger_remediation` needs a "revised mini-plan" message. Both could be
generated by an LLM call, or composed deterministically from the data
already computed (mastery score, urgency, weak prerequisites).

## Options considered

- **LLM call per justification/plan.** More natural phrasing, but adds
  latency and a failure mode (validation/network) to two nodes whose
  actual decision-making (topic selection, remediation trigger) is
  already fully deterministic — the model would only be paraphrasing
  numbers the code already has. It would also need its own schema and
  guardrail for consistency with the rest of the project's "never
  free-text" rule.
- **Deterministic string composition.** No extra model call, no extra
  failure mode, trivially unit-testable (`assert "Variables" in
  plan.suggested_actions[0]`), and the output is fully explainable —
  every clause traces to a specific number.

## Choice

Deterministic composition (`agents/recommend.py`'s `justification`
f-string, `agents/remediation.py`'s `reason`/`message`/
`suggested_actions`). Both remain simple sentence templates over already-
computed values.

## Consequences

- Justifications and remediation messages are stable and testable
  without a fake LLM response, but they read as templated, not
  conversational. Revisit if user feedback wants more natural phrasing —
  at that point it becomes a genuine generation task with its own schema,
  not a free-text patch on top of this.
